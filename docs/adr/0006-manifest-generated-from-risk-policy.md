# The agent tool manifest is generated from the risk policy

"Capability absent, not merely denied" is the Assist trust model's core protection, and enforcement-by-convention rots. We decided `IToolRiskPolicy` (in Shop.Application) is the single source of tool↔Risk-Class mapping; the MCP tool manifest is *generated* by filtering it together with the kill switches, so `NEVER` tools and disabled tools are simply never registered — a pay tool cannot exist in the surface. Shop.Mcp's enforcement is authoritative (a rogue client can connect to `/mcp` directly); the AgentLoop's pre-checks are fail-fast optimizations only. `scope=agent` JWTs are minted server-side per chat turn (60s TTL, never sent to any client) and are rejected at every REST endpoint. Chat requires login in v1; anonymous agent tokens exist only for the three public READ tools.
